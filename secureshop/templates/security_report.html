Finding 1: Insecure Direct Object Reference (IDOR)

High Severity | OWASP A01:2021
WHAT?
Horizontal authorization bypass permitting authenticated users to access confidential invoices belonging to arbitrary accounts.
WHERE?
GET /orders/<order_id> parameter order_id in URL path.
WHY?
Server-side route handler performs database fetch using identifier supplied by client without cross-verifying ownership with session['user_id'].
IMPACT?
Confidentiality breach: Customer John Doe (user) can extract full delivery addresses, customer names, item lists, and billing totals for all customers.
EVIDENCE?
[Placeholder - Replace with actual screenshot / HTTP response header from ZAP]
Navigating to /orders/2 while logged in as user (id=2) yields HTTP 200 with Alice Walker's confidential shipping address.
REMEDIATION?
Implemented ownership assertion: if order['user_id'] != session['user_id'] and session['role'] != 'admin': abort(403).
RETEST?
[Placeholder - Replace with actual retest output] In Fixed Mode, navigating to /orders/2 immediately aborts with HTTP 403 Forbidden and writes event to logs/security.log.

Finding 2: SQL Injection in Product Search

High Severity | OWASP A03:2021
WHAT?
Improper neutralization of special elements used in an SQL command (CWE-89).
WHERE?
GET /products?q=<query> query string parameter q.
WHY?
Direct string interpolation (f"SELECT ... LIKE '%{q}%'") allowing user input to escape SQL string literal delimiters.
IMPACT?
Data exposure. Allows unintended database queries and arbitrary row enumeration across local database tables.
EVIDENCE?
[Placeholder - Replace with actual ZAP SQL injection alert screenshot]
Payload ' OR 1=1 -- forces truth condition, returning all products in database.
REMEDIATION?
Parameterized query implementation: cursor.execute("SELECT ... WHERE name LIKE ? OR description LIKE ?", (f"%{q}%", f"%{q}%")).
RETEST?
[Placeholder - Replace with actual retest output] Payload ' OR 1=1 -- treated as literal search string; returns 0 matches without syntax error.

Finding 3: Security Misconfiguration (Debug Mode & Missing Headers)

Medium Severity | OWASP A05:2021
WHAT?
Debug mode enabled in runtime environment; missing defense-in-depth HTTP headers (X-Frame-Options, CSP, nosniff).
WHERE?
Global HTTP response headers and GET /debug/crash-test.
WHY?
Development convenience settings retained in active configuration; lack of header injection middleware.
IMPACT?
Leakage of server path, framework internals, environment variables; susceptibility to Clickjacking attacks.
EVIDENCE?
[Placeholder - Replace with actual ZAP Header Check alert]
ZAP flags "Anti-clickjacking Header Not Set" (10020) and "Content-Security-Policy Header Not Set" (10038).
REMEDIATION?
Disabled DEBUG=False, registered custom error handlers, added security headers middleware (X-Frame-Options: DENY, Content-Security-Policy).
RETEST?
[Placeholder - Replace with actual retest output] Rescanning with ZAP confirms absence of missing header alerts; headers verified via curl / browser inspector.
