OWASP A01:2021

Broken Access Control (IDOR)

{{ 'VULNERABLE' if security_mode == 'vulnerable' else 'REMEDIATED' }}
Affected Location
GET /orders/<order_id> (Order Details Invoice)
Why it exists (Root Cause)

The application accepts an object identifier directly from the URL parameter and queries the database without validating whether the currently authenticated session owns the requested resource or possesses administrative authorization.

Security Impact

Horizontal privilege escalation. An authenticated customer (e.g. user) can enumerate order IDs and view sensitive billing details, customer names, emails, and confidential shipping destinations of other customers (e.g. alice).

Safe Validation Procedure
  1. Log in as standard customer user (owns Order #1 and #3).
  2. Navigate to your order list at /orders and click "View Invoice" on Order #1.
  3. Manually alter the URL in your browser address bar from /orders/1 to /orders/2 (Order #2 belongs to alice).
  4. Observed in Vulnerable Mode: Alice's private invoice and confidential Texas delivery address are displayed.
  5. Observed in Fixed Mode: The server blocks access, returns 403 Forbidden, and writes an unauthorized attempt to the audit log.
http://127.0.0.1:8080/orders/2
Remediation Implementation

Enforced strict server-side ownership authorization: if order['user_id'] != session['user_id'] and session['role'] != 'admin': abort(403).

OWASP A03:2021

SQL Injection (Search Functionality)

{{ 'VULNERABLE' if security_mode == 'vulnerable' else 'REMEDIATED' }}
Affected Location
GET /products?q=<payload> (Product Search Query)
Why it exists (Root Cause)

The search endpoint dynamically formats the SQL query string using Python f-strings / raw string concatenation without parameterized placeholders.

Security Impact

Untrusted input can break out of the SQL syntax context, allowing arbitrary data queries or information extraction across tables within the local database.

Safe Validation Procedure
  1. Open the Search bar on the top navigation bar or navigate to /products.
  2. Enter the safe local boolean test payload: ' OR '1'='1' -- or ' OR 1=1 --.
  3. Observed in Vulnerable Mode: The SQL query evaluates to TRUE for all rows, returning the entire product database regardless of search terms.
  4. Observed in Fixed Mode: The parameterized query treats the entire string as a literal text search for ' OR '1'='1' --, returning zero matches safely.
' OR 1=1 --
Remediation Implementation

Replaced dynamic string formatting with parameterized prepared query: cursor.execute("SELECT * FROM products WHERE name LIKE ? OR description LIKE ?", (f"%{q}%", f"%{q}%")).

OWASP A05:2021

Security Misconfiguration (Debug Mode & Missing Headers)

{{ 'VULNERABLE' if security_mode == 'vulnerable' else 'REMEDIATED' }}
Affected Location
Application server runtime configuration, HTTP response headers, GET /debug/crash-test
Why it exists (Root Cause)

The application runs with Flask DEBUG=True and lacks standard defensive HTTP response headers (CSP, X-Frame-Options, X-Content-Type-Options). Unhandled exceptions expose raw Python stack traces and file paths.

Security Impact

Information leakage regarding directory structure, Python runtime version, internal variable states, and vulnerability to UI redressing (Clickjacking) due to missing frame restrictions.

Safe Validation Procedure
  1. Navigate to the test exception route: /debug/crash-test.
  2. Observed in Vulnerable Mode: Full interactive traceback and internal variables are displayed to the client; HTTP response headers omit security controls.
  3. Observed in Fixed Mode: Clean, sanitized 500 error page displayed without stack traces; HTTP headers include X-Frame-Options: DENY and Content-Security-Policy.
Remediation Implementation

Set debug=False, registered custom error handlers, and injected hardened headers via @app.after_request middleware.

OWASP A07:2021

Identification & Authentication Failures

{{ 'VULNERABLE' if security_mode == 'vulnerable' else 'REMEDIATED' }}
Affected Location
Session cookie flags (session cookie) & User Registration password policy (/register)
Why it exists (Root Cause)

Session cookies created without HttpOnly or SameSite attributes; registration does not enforce password length or complexity rules.

Safe Validation Procedure
  1. Open browser Developer Tools (F12) → Application / Storage → Cookies → http://127.0.0.1:8080.
  2. Inspect the session cookie flags.
  3. Observed in Vulnerable Mode: HttpOnly is false, SameSite is None, allowing client JavaScript access via document.cookie.
  4. Observed in Fixed Mode: HttpOnly is set to True (blocking JavaScript theft), SameSite=Lax.
Remediation Implementation

Configured app.config['SESSION_COOKIE_HTTPONLY'] = True, SESSION_COOKIE_SAMESITE = 'Lax', and added regex password complexity verification on signup.

OWASP A09:2021

Security Logging and Monitoring Failures

{{ 'VULNERABLE' if security_mode == 'vulnerable' else 'REMEDIATED' }}
Affected Location
Application event logging (Authentication, Authorization, Administrative changes)
Why it exists (Root Cause)

Critical security events (failed logins, unauthorized access attempts, admin actions) occur silently without producing an audit trail, making incident detection impossible.

Safe Validation Procedure
  1. Trigger a deliberate failed login by submitting an incorrect password at /login.
  2. Attempt an unauthorized IDOR access to /orders/2 while logged in as user.
  3. Observed in Vulnerable Mode: No security logs are generated; administrators are unaware of hostile probing.
  4. Observed in Fixed Mode: High-severity events are immediately appended to logs/security.log and visible in the Audit Log section below.
Remediation Implementation

Implemented structured security event logging helper log_security_event() writing to both SQLite table and persistent file logs/security.log.
